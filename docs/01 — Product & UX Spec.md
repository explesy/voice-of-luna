# Product & UX Spec

## Voice Trainer — Web App

# Цель продукта

Дать пользователю ощущение естественного голосового разговора, сохранив качество сильной текстовой модели и значительно более строгий контроль над ходом сессии, чем в обычном Live-режиме.

# Основной пользовательский сценарий

Пользователь открывает веб\-приложение, выбирает тренировочный проект и длительность сессии, разрешает доступ к микрофону и начинает говорить. Приложение слушает, распознаёт реплику, передаёт её в LLM вместе с текущим состоянием тренировки, валидирует предложенное действие и озвучивает ответ. В конце создаётся краткий debrief и session log.

# Job to be done

Когда я тренирую сложный разговор голосом, я хочу реагировать спонтанно, а не редактировать письменный ответ, но при этом хочу, чтобы AI-тренер точно соблюдал структуру упражнения, выдерживал мои паузы и не завершал работу раньше времени.

# Главный UX

Основной экран должен быть минимальным. Во время активной сессии видны таймер, текущий режим «слушаю / думаю / говорю», кнопки Pause, End, Repeat last line и Report protocol issue. Транскрипт по умолчанию скрыт или визуально вторичен; его можно раскрыть для отладки или после сессии.

# Старт сессии

Перед началом пользователь выбирает проект, сценарий/режим, длительность и при необходимости голос. Приложение проверяет микрофон и звук. В личном Codex-connected режиме он также показывает понятный статус «локальный Codex подключён к этой учётной записи» или «нужно подключить»; сам OAuth-flow проходит в локальном companion, а не внутри session screen. Для MVP достаточно одного пользователя и одного заранее настроенного training project; сложный onboarding не нужен.

# Голосовой цикл

Пользователь говорит без push-to-talk. Endpointing определяет конец смысловой реплики, но допускает длинные паузы. После commit аудио распознаётся в текст. Controller формирует состояние и контекст для LLM. Ответ LLM проходит validation. Озвучивание начинается потоково, как только доступна безопасная для воспроизведения законченная фраза.

# Patient silence

Короткое молчание не должно автоматически вызывать новую реплику ассистента. В эмоционально сложных сценах timeout конца реплики должен быть длиннее, чем у обычного voice assistant. В дальнейшем приложение может адаптировать endpointing к текущему режиму и истории пауз пользователя.

# Barge-in

Если пользователь начинает говорить во время TTS, воспроизведение немедленно останавливается, входящий голос становится новым пользовательским turn, а остаток незавершённого текста помечается как неуслышанный. Нельзя требовать ждать окончания длинного ответа.

# Replay

Кнопка Repeat last line повторяет именно последнюю услышанную реплику. Протокольный replay сцены использует сохранённый исходный utterance, а не просит LLM заново сочинить похожую формулировку.

# Поведение тренера

Ответы в активной сцене короткие и разговорные. Модель не должна превращать каждый ход в анализ или совет. Рефлексия проводится только в разрешённых фазах. Готовый «идеальный ответ» пользователю не выдаётся, если задача этапа — самостоятельная попытка. Модель не имеет права самостоятельно объявить тренировку завершённой до разрешения controller.

# Debrief

После завершения показывается короткая сводка: какие сцены были пройдены, где пользователь зависал/прерывал, какие protocol violations произошли, что было предметом replay и какие наблюдения стоит перенести в следующую сессию. Полный transcript остаётся доступным отдельно.

# MVP-функции

MVP включает browser microphone input, automatic turn detection, STT, text LLM, TTS, streaming/low-latency transport, session timer, finite-state controller, exact replay, barge-in, скрываемый transcript, session log и простой debrief. Мультипользовательский billing, marketplace сценариев, мобильные native apps и сложная аналитика в MVP не входят.

# Критерии качества

Сессия не завершается моделью раньше разрешённого момента. Обязательные этапы нельзя пропустить неподдерживаемым переходом. Replay дословно воспроизводит сохранённую реплику. Пользователь может выдержать несколько секунд тишины без навязчивой реплики ассистента. Barge-in останавливает TTS без заметного ожидания. После сбоя можно восстановить состояние из лога. В обычном ходе разговора latency должна ощущаться достаточно короткой для диалога; конкретные численные SLO определяются после первого измеряемого prototype.

# Доступность и приватность

Пользователь всегда может остановить запись и завершить сессию. Индикатор микрофона должен быть однозначным. API-ключи и OAuth-токены никогда не отправляются в браузер. В Codex-connected режиме пользователь должен видеть, что запросы выполняются от его локальной учётной записи и расходуют её доступный лимит; отключение режима удаляет только локальную связь приложения с runtime, а не требует хранить пароль в проекте. Сырой audio по умолчанию не требуется хранить после распознавания; transcript/session state можно хранить с настраиваемым retention. Для чувствительных проектов должна быть возможность удалить session data.

# Не-цели первой версии

Не пытаться воспроизвести весь интерфейс ChatGPT. Не делать универсального терапевта. Не строить сложную автономную память до появления рабочего voice loop. Не оптимизировать под десятки провайдеров до проверки основного пользовательского сценария. Не предлагать посетителям сайта войти в личный ChatGPT/Codex-аккаунт через backend проекта: такой multi-user OAuth-продукт не входит в MVP.
