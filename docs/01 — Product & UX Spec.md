# Product & UX Spec

## Voice of Luna — Personal Voice Interface

# Цель продукта

Дать пользователю ощущение естественного голосового разговора, сохранив качество сильной текстовой модели и контроль над приватностью, паузами и прерыванием ответа.

# Основной пользовательский сценарий

Пользователь открывает веб\-приложение, убеждается, что локальный Codex подключён, разрешает доступ к микрофону и начинает говорить. Приложение слушает, распознаёт реплику, передаёт текст в LLM и озвучивает ответ. История разговора остаётся доступной локально и может быть очищена.

# Job to be done

Когда я хочу поговорить с сильной моделью, я хочу отвечать спонтанно голосом, а не редактировать письменный ответ; при этом я хочу спокойно думать, перебивать длинный ответ и понимать, где находятся мои данные и от чьей учётной записи работает модель.

# Главный UX

Основной экран должен быть минимальным. Во время активного разговора видны текущий режим «слушаю / думаю / говорю», кнопки Mute, Stop speaking и End. Транскрипт по умолчанию вторичен, но раскрывается одним действием. В header отображаются локальный статус Codex и используемый голос; технические детали не мешают разговору.

# Старт сессии

Перед началом приложение проверяет микрофон, звук и доступность local Codex bridge. Пользователь выбирает голос и при необходимости открывает настройку provider-а. Экран показывает понятный статус «локальный Codex подключён» или «нужно подключить»; сам login проходит в Codex на машине владельца, а не внутри session screen.

# Голосовой цикл

Пользователь говорит без push-to-talk. Endpointing определяет конец смысловой реплики, но допускает длинные паузы. После commit аудио распознаётся в текст. Controller формирует состояние и контекст для LLM. Ответ LLM проходит validation. Озвучивание начинается потоково, как только доступна безопасная для воспроизведения законченная фраза.

# Patient silence

Короткое молчание не должно автоматически вызывать новую реплику ассистента. В эмоционально сложных сценах timeout конца реплики должен быть длиннее, чем у обычного voice assistant. В дальнейшем приложение может адаптировать endpointing к текущему режиму и истории пауз пользователя.

# Barge-in

Если пользователь начинает говорить во время TTS, воспроизведение немедленно останавливается, входящий голос становится новым пользовательским turn, а остаток незавершённого текста помечается как неуслышанный. Нельзя требовать ждать окончания длинного ответа.

# History

Пользователь может открыть transcript текущего разговора, скопировать или удалить его целиком. Повтор последней реплики — обычная локальная функция TTS и не запрашивает модель заново.

# Поведение модели

В базовом режиме приложение не навязывает сценарий: модель отвечает на запрос пользователя. System prompt ограничивается лаконичным разговорным стилем, запретом на незапрошенные инструменты и явным сообщением о том, что это голосовая беседа. Предметные правила могут добавлять plugins.

# Завершение

End немедленно останавливает микрофон и TTS. Приложение предлагает сохранить или удалить локальный transcript; автоматический анализ разговора в MVP не выполняется.

# MVP-функции

MVP включает browser microphone input, automatic turn detection, STT, text LLM через local Codex bridge, TTS, low-latency transport, barge-in, скрываемый transcript и удаление истории. Мультипользовательские аккаунты, billing, marketplace plugins, сложная аналитика и тренажёрные сценарии в MVP не входят.

# Критерии качества

Пользователь может выдержать несколько секунд тишины без навязчивой реплики. Barge-in останавливает TTS без заметного ожидания. Статус микрофона и Codex не вводит в заблуждение. В обычном ходе разговора latency должна ощущаться достаточно короткой для диалога; конкретные SLO определяются после первого измеряемого prototype.

# Доступность и приватность

Пользователь всегда может остановить запись и завершить сессию. Индикатор микрофона должен быть однозначным. API-ключи и OAuth-токены никогда не отправляются в браузер. В Codex-connected режиме пользователь должен видеть, что запросы выполняются от его локальной учётной записи и расходуют её доступный лимит; отключение режима удаляет только локальную связь приложения с runtime, а не требует хранить пароль в проекте. Сырой audio по умолчанию не требуется хранить после распознавания; transcript/session state можно хранить с настраиваемым retention. Для чувствительных проектов должна быть возможность удалить session data.

# Не-цели первой версии

Не пытаться воспроизвести весь интерфейс ChatGPT. Не делать универсального терапевта. Не строить сложную автономную память до появления рабочего voice loop. Не оптимизировать под десятки провайдеров до проверки основного пользовательского сценария. Не предлагать посетителям сайта войти в личный ChatGPT/Codex-аккаунт через backend проекта: такой multi-user OAuth-продукт не входит в MVP. Не добавлять сейчас личный training protocol в core.
