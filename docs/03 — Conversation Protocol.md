# Conversation Protocol

## Voice Trainer — Web App

# Основной принцип

Conversation Protocol исполняется приложением, а не доверием к инструкциям LLM. Модель предлагает содержательную реплику и действие. Controller принимает или отклоняет proposed action на основе текущего состояния.

# Базовые состояния

PREPARE: настройка проекта, цели и длительности.  
SCENE: AI находится в роли собеседника и даёт очередную сценическую реплику.  
WAIT\_USER: приложение слушает самостоятельную реакцию пользователя.  
REFLECT: разрешены короткие вопросы о реакции пользователя.  
CONTINUE\_SCENE: возврат к роли и продолжение диалога.  
REPLAY: повтор конкретного сохранённого участка сцены.  
DEBRIEF: разбор после практики.  
END: финальное состояние, новые сценические turns запрещены.

# Право на переход

Переход выполняет только Controller. LLM возвращает proposed\_action, например STAY\_IN\_SCENE, ASK\_REFLECTION, RETURN\_TO\_SCENE, REQUEST\_REPLAY, MOVE\_TO\_DEBRIEF. Validator сравнивает его с разрешёнными transitions. Недопустимый action игнорируется, логируется и заменяется безопасным действием для текущей фазы.

# Контроль времени

Session clock является источником истины. LLM получает remaining\_time как контекст, но не определяет его. Фраза модели о завершении не переводит сессию в DEBRIEF. До окончания обязательных этапов и разрешения Controller команда завершения отклоняется. Пользователь при этом всегда может явно нажать End.

# Обязательные этапы

Training project может задавать ordered или flexible requirements, например самостоятельная попытка, продолжение сцены, рефлексия, replay и итог. Controller хранит unfinished\_requirements. Переход в DEBRIEF разрешён только когда выполнены требования или пользователь вручную завершил сессию.

# Самостоятельная попытка

Если текущий шаг требует user attempt, модель не выдаёт готовый правильный ответ до попытки пользователя. Допустимы только сценическая реплика, молчание/ожидание или очень короткое уточнение, разрешённое protocol config.

# Рефлексия

Количество последовательных reflection questions ограничено конфигурацией. После достижения лимита Controller требует возврат к сцене или следующий обязательный этап. Это предотвращает превращение всей тренировки в бесконечный анализ.

# Exact replay

Каждая значимая сценическая реплика сохраняется как immutable spoken utterance. REPLAY указывает replay\_source\_turn\_id. Для точного повтора TTS получает сохранённый approved spoken text напрямую; LLM не генерирует его повторно. После replay состояние возвращается к определённому protocol step, например WAIT\_USER.

# Repeat last line

Пользовательская команда повторить последнюю реплику отличается от protocol replay. Она просто повторяет последний фактически услышанный assistant utterance и не изменяет фазу тренировки.

# Patient silence

Endpointing не должен считать естественную паузу завершением эмоциональной работы. Controller может устанавливать silence profile: normal, patient или manual. В patient режиме допустим более длинный silence window. Пока turn не committed, LLM не получает пустой user message и не начинает заполнять паузу.

# Barge-in

Пользователь имеет приоритет над playback. Начало речи во время TTS создаёт interruption event, немедленно останавливает локальное воспроизведение и отменяет дальнейшую доставку аудио. В контекст следующего turn передаётся только та часть ответа, которую пользователь реально мог услышать, либо специальный interrupted marker.

# Контракт LLM

Рекомендуемый результат:  
spoken\_text — фраза для пользователя; должна быть короткой в active scene.  
proposed\_action — одно действие из разрешённого enum.  
reason\_code — краткая машинная причина, например CONTINUE\_ROLEPLAY или USER\_NEEDS\_REFLECTION.  
memory\_note — необязательное наблюдение для post-session summarizer; само по себе не меняет persistent memory.

# Validator

Validator проверяет JSON/schema, длину spoken\_text, допустимость proposed\_action, текущую фазу, лимит reflection questions, unfinished requirements, право на завершение и replay invariants. При нарушении он может выбрать fallback: оставить текущую фазу, попросить LLM regenerate с узким repair prompt или использовать заранее заданную короткую фразу.

# Prompt layers

Слой 1: общие требования безопасности и voice brevity.  
Слой 2: project protocol — цель тренировки, роли и особые правила.  
Слой 3: current session goal.  
Слой 4: machine state — phase, counters, timers, requirements.  
Слой 5: relevant memory и последние turns.  
Слой 6: текущая user utterance.  
Machine state передаётся в явном структурированном виде и считается более авторитетным, чем произвольные фразы в conversational history.

# Стиль активной сцены

В SCENE и CONTINUE\_SCENE предпочтительны короткие естественные реплики. Ассистент не должен постоянно объяснять пользователю процесс. Meta-commentary минимален. В REFLECT допускается один короткий вопрос за ход. В DEBRIEF можно использовать более длинный аналитический ответ.

# Завершение

Нормальное завершение: Controller видит, что обязательные требования закрыты и время подходит к концу, затем разрешает MOVE\_TO\_DEBRIEF. Пользователь может завершить раньше вручную. После END microphone capture останавливается и никакие новые provider calls не инициируются.

# Ошибки и восстановление

Если STT не уверен, можно запросить короткое уточнение без продвижения state. Если LLM output не проходит schema, выполняется retry/repair без озвучивания плохого текста. Если TTS падает, текст остаётся доступен и можно повторить синтез. После WebSocket reconnect backend восстанавливает state по session/event log.

# Минимальный набор protocol tests

Модель пытается закончить сессию за несколько минут до конца — Validator блокирует переход. Модель предлагает третий reflection question при лимите два — переход блокируется. Replay воспроизводит исходный utterance byte-for-text, а не новую вариацию. Пользователь молчит несколько секунд — приложение продолжает слушать. Пользователь перебивает TTS — playback прекращается. Пользователь вручную нажимает End — завершение разрешается из любой фазы.
