# Voice Trainer — Web App

## PROJECT README

# Назначение

Voice Trainer — веб\-приложение для голосового общения с сильной текстовой LLM в задачах, где стандартный Live/voice-режим недостаточно строго соблюдает протокол. Пользователь говорит голосом, приложение распознаёт речь, передаёт текст в LLM, проверяет и оркестрирует ответ, затем озвучивает его. Субъективно это голосовой разговор, но «мозг» и контроль сценария остаются в текстовом контуре.

# Исходная проблема

В тренировках сложных диалогов голосовая модель может преждевременно завершать сессию, заполнять полезные паузы, пропускать обязательные этапы, менять формулировку при replay, давать готовые ответы вместо тренировки или терять состояние протокола. Одних инструкций недостаточно: часть правил должна исполняться детерминированным контроллером приложения.

# Продуктовая гипотеза

Качество голосового взаимодействия можно повысить, если разделить интеллект и управление. LLM отвечает за понимание контекста и генерацию содержательной реплики. Приложение отвечает за время, фазу сессии, допустимые переходы, точный replay, количество рефлексивных вопросов, паузы, прерывания и завершение.

# Текущие решения

Продукт делаем как web application, работающий в современном браузере на desktop и mobile. Нативное Mac-приложение не требуется. Frontend получает доступ к микрофону через browser APIs. Все секретные API-ключи хранятся только на backend. Интеграция с LLM/STT/TTS строится через официальные provider APIs; автоматизация consumer ChatGPT UI не является частью архитектуры. Конкретные модели должны задаваться конфигурацией и заменяться без переписывания приложения.

Для личного локального MVP допускается отдельный **Codex-connected mode**: пользователь один раз авторизует локальный companion через свою ChatGPT/Codex-учётную запись, а тот запускает поддерживаемый Codex runtime для LLM-turns. Браузер и web backend не получают OAuth access/refresh tokens. Это не публичная «Sign in with ChatGPT» для посетителей сайта и не способ обходить лимиты подписки: вызовы расходуют доступный лимит Codex этой учётной записи. API-key mode остаётся независимым fallback для server deployment и будущего multi-user продукта.

# Принципы

Voice-first: во время тренировки пользователь не обязан читать или печатать. Protocol-first: контроллер важнее свободного поведения модели. Patient silence: пауза пользователя не считается ошибкой и не должна автоматически заполняться речью. Exact replay: повтор сцены воспроизводит сохранённую исходную реплику. Barge-in: пользователь может перебить синтезированную речь. Observable: каждое нарушение протокола можно восстановить по session log. Provider-agnostic: STT, LLM и TTS заменяемы. Personal-account-safe: долгоживущая авторизация Codex остаётся на устройстве владельца, а не в браузере или общем сервере.

# Граница с проектом Relationship

Voice Trainer возник из практики диалогов, но код и общая архитектура должны оставаться универсальными. Конкретные персональные сценарии, история тренировок и содержательные материалы проекта Relationship не дублируются в этой папке. Приложение должно уметь загружать такой контекст как отдельную конфигурацию/проект.

# Текущий статус

Сформулированы продуктовая гипотеза, web-first архитектура, требования к controller layer и первоначальный MVP. Следующий инженерный шаг — короткий technical spike: подтвердить локальный Codex-connected LLM turn без передачи токенов в браузер, одновременно сохранив API-key adapter. Затем создать минимальный web prototype: microphone → STT → text LLM → validated response → streaming TTS → speaker.
