# Voice of Luna — Personal Voice Interface

## PROJECT README

# Назначение

Voice of Luna — личное web-приложение для простого голосового общения с сильной текстовой LLM. Пользователь говорит, приложение распознаёт речь, передаёт текст в модель и озвучивает ответ. Субъективно это живой разговор, но «мозг» остаётся в качественном текстовом контуре.

# Исходная проблема

Стандартные Live/voice-режимы могут быть менее точными и управляемыми, чем сильная текстовая модель. Нужен небольшой личный инструмент, где можно говорить естественно, видеть честное состояние микрофона и в любой момент перебить ответ — без ручной работы с ключами или сложного интерфейса чата.

# Продуктовая гипотеза

Качество голосового взаимодействия можно повысить, если разделить интеллект и голосовой transport. LLM отвечает за понимание контекста и содержательную реплику. Приложение отвечает за захват голоса, turn-taking, прерывание ответа, воспроизведение и прозрачность приватных данных.

# Текущие решения

Продукт делаем как web application, работающий в современном браузере на desktop и mobile. Нативное Mac-приложение не требуется. Frontend получает доступ к микрофону через browser APIs. Все секретные API-ключи хранятся только на backend. Интеграция с LLM/STT/TTS строится через официальные provider APIs; автоматизация consumer ChatGPT UI не является частью архитектуры. Конкретные модели должны задаваться конфигурацией и заменяться без переписывания приложения.

Для личного локального MVP допускается отдельный **Codex-connected mode**: пользователь один раз авторизует локальный companion через свою ChatGPT/Codex-учётную запись, а тот запускает поддерживаемый Codex runtime для LLM-turns. Браузер и web backend не получают OAuth access/refresh tokens. Это не публичная «Sign in with ChatGPT» для посетителей сайта и не способ обходить лимиты подписки: вызовы расходуют доступный лимит Codex этой учётной записи. API-key mode остаётся независимым fallback для server deployment и будущего multi-user продукта.

# Принципы

Voice-first: во время разговора пользователь не обязан читать или печатать. Responsive: короткий путь от конца реплики до начала ответа. Patient silence: пауза пользователя не считается ошибкой и не должна автоматически заполняться речью. Barge-in: пользователь может перебить синтезированную речь. Transparent: всегда видны состояния «слушаю / думаю / говорю» и источник модели. Provider-agnostic: STT, LLM и TTS заменяемы. Personal-account-safe: долгоживущая авторизация Codex остаётся на устройстве владельца, а не в браузере или общем сервере.

# Граница с проектом Relationship

Приложение остаётся нейтральным ядром. Личные тренировочные сценарии, протоколы и контент не входят в базовый продукт: позднее они смогут подключаться как отдельные plugins с ограниченными hooks, без доступа к OAuth-credential или аудиопотоку.

# Текущий статус

Сформулированы продуктовая гипотеза, web-first архитектура и первоначальный MVP. Следующий инженерный шаг — минимальный локальный prototype: browser microphone → STT → local Codex bridge → text response → TTS → speaker.
